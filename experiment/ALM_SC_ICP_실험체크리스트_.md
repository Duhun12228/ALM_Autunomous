# ALM Scan Context–ICP 초기 위치 정합 실험표

## 1. 실험 목적

한 장소에서 동일한 위치와 방향으로 로봇을 반복 배치하여, 초기 위치 정합 실패의 원인을 다음 순서로 분리한다.

```text
Scan Context 후보 품질 확인
→ ICP 수렴 범위 개선
→ ICP 입력 점군 개선
→ 초기화 시간 단축
→ 최종 조합 검증
```

이번 실험에서는 **한 번에 변수 하나만 변경**한다. 여러 값을 동시에 바꾸면 어떤 변경이 성능에 영향을 주었는지 판단하기 어렵다.

# 4. 실험 1 — Scan Context 높이 범위

## 왜 하는가

천장, 배관, 높은 구조물이 Scan Context descriptor에 포함되어 장소 구분력을 낮추는지 확인한다.

## 기대 효과

적절한 `z_max`를 사용하면 천장 정보는 줄고 벽, 기둥, 선반처럼 장소를 구분하는 구조는 남아 정답 후보 순위가 올라갈 수 있다.

## 변수 통제

| 구분 | 내용 |
|---|---|
| 변경 변수 | Scan Context `z_min`, `z_max` |
| 고정 변수 | DB step, Ring/Sector, max radius, 후보 수, ICP 설정, 로봇 위치·방향 |
| 평가 대상 | 정답 후보 순위와 SC 후보 안정성 |
| 반복 횟수 | 각 설정 3회 |
| 주의 | 각 높이 범위마다 SC DB를 새로 생성 |

# 5. 실험 2 — SC DB 가상 위치 간격

## 왜 하는가

현재 DB 위치 간격이 크면 실제 로봇 위치와 가장 가까운 후보도 수십 cm 떨어질 수 있다. DB step을 줄였을 때 정답 후보 위치가 실제 위치에 가까워지는지 확인한다.

## 기대 효과

DB step을 줄이면 실제 위치 근처에 더 많은 가상 후보가 생겨 Scan Context 후보의 위치 오차가 줄고 ICP가 수렴하기 쉬워질 수 있다.

| 평가 대상 | 정답 후보 순위, 후보 위치 정확도, 검색 시간 |
| 반복 횟수 | 각 설정 3회 |

# 6. 실험 3 — 기존 ICP와 Coarse-to-Fine ICP 비교

## 왜 하는가

현재 ICP의 최대 대응 거리가 약 0.1 m라면 Scan Context 후보가 실제 위치에서 수십 cm 벗어났을 때 대응점을 충분히 찾지 못할 수 있다.

## 기대 효과

Coarse ICP가 큰 초기 오차를 먼저 줄이고, Fine ICP가 남은 오차를 정밀하게 보정하여 수렴률과 최종 정확도를 함께 높인다.

## 중요 통제 조건

이 실험은 Scan Context 성능과 분리해야 한다.  
**같은 source cloud와 같은 초기 후보를 저장해 두고 모든 ICP 설정에 동일하게 사용한다.**

## 변수 통제

| 구분 | 내용 |
|---|---|
| 변경 변수 | ICP 방식과 correspondence distance |
| 고정 변수 | 동일 source cloud, 동일 target map, 동일 initial guess, 동일 voxel 외 조건 |
| 평가 대상 | 수렴 여부, 최종 위치 정확도, 처리 시간 |
| 반복 횟수 | 동일 입력으로 각 설정 3회 |

## 실험 설정

| 설정 ID | ICP 구성 | Coarse 대응 거리 | Fine 대응 거리 | 설명 |

| I1 | 기존 단일 ICP | - | 0.1 m | 현재 기준 |
| I2 | 단일 ICP | - | 0.5 m | 대응 거리만 확대 |
| I3 | Coarse-to-Fine | 1.0 m | 0.3 m | 권장 구조 |

권장 voxel 시작값:

# 7. 실험 4 — ICP 입력 점군 프레임 수

## 왜 하는가

현재 Scan Context는 여러 프레임을 누적하지만 ICP는 단일 프레임을 사용한다. MID-360 단일 프레임은 희소하고 프레임마다 점 분포가 달라 ICP 결과가 불안정할 수 있다.

## 기대 효과

누적 점군을 ICP source로 사용하면 점 밀도가 높아지고 후보마다 동일한 점군을 사용하므로 fitness와 정합 결과가 더 안정될 수 있다.

## 변수 통제

| 구분 | 내용 |
|---|---|
| 변경 변수 | ICP source 누적 프레임 수 |
| 고정 변수 | 실험 3에서 선택한 ICP 설정, 동일 PCD, 동일 initial guess, 동일 위치·방향 |
| 평가 대상 | ICP 성공률, fitness 변동, 위치 정확도, 처리 시간 |
| 반복 횟수 | 각 설정 3회 |
| 주의 | 점군 누적 중 차량 완전 정지 |

## 실험 설정

| 설정 ID | ICP source | 설명 |
|---|---:|---|
| F1 | 1프레임 | 현재 기준 |
| F2 | 5프레임 누적 | 중간 밀도 |
| F3 | 10프레임 누적 | SC와 같은 수준의 누적 |

# 9. 실험 6 — 후보 개수 조정

## 이 실험은 언제 하는가

실험 0~5 결과에서 **정답 후보가 자주 6위 이하로 나올 때만 수행한다.**  
정답 후보가 이미 Top-5 안에 있는데 ICP가 실패한다면 후보 수를 늘릴 필요가 없다.

## 왜 하는가

올바른 후보가 기존 `max_candidates=5` 밖에 있어 ICP 시도 자체가 되지 않는지 확인한다.

## 기대 효과

정답 후보가 6~10위에 자주 존재한다면 실제 ICP 후보 수를 늘려 초기화 성공률을 높일 수 있다.

## 변수 통제

| 구분 | 내용 |
|---|---|
| 변경 변수 | `topk`, `max_candidates` |
| 고정 변수 | 최종 z 범위, DB step, ICP 설정, 누적 프레임, timeout |
| 평가 대상 | 성공률과 초기화 시간 |
| 반복 횟수 | 각 설정 3회 |

## 실험 설정

| C2 | 50 | 5 |
